# NOMI 网站版本规划

更新：2026-11-11。版本按**整站完成度**推进：每个版本都包含个人介绍、个人作品、抖音作品和留言四个模块；后续版本是在完整站点上提升质量，不把单个模块拆成独立版本。

## 产品概述

- **核心定位**：Y2K 动漫风格的 NOMI 个人品牌展示与联系网站。
- **核心价值**：让访客认识 NOMI、连续浏览图片和文章、关注抖音并私下留言。
- **目标用户**：想了解 NOMI 的访客与希望展示内容、收集反馈的 NOMI。
- **当前边界**：不做后台、数据库留言历史、公开留言墙、自动抓取抖音、站内视频播放、图片弹窗或文章详情页。

## 核心需求清单

| 需求 | 优先级 | 所属整站版本 |
|---|---|---|
| IP、昵称、个人介绍与兴趣/内容方向 | P0 | V0.1 起 |
| 个人图片与文章全文混排、手动排序 | P0 | V0.1 起 |
| 抖音作品封面标题卡片、统一跳主页 | P0 | V0.1 起 |
| 昵称、微信号、留言必填及状态反馈 | P0 | V0.1 起 |

| Y2K 视觉系统与正式素材 | P1 | V0.2 |
| 空态、失败、超时、可访问性和性能 | P1 | V0.3 |
| 部署、域名、发布文档、回归和备份 | P0 | V1.0 |

## 版本规划路线图

### V0.1 MVP - 整站可用，跑通完整用户旅程

**目标**：用最小但完整的站点验证“认识 NOMI → 浏览作品 → 关注抖音 → 留言联系”的核心价值。四个模块全部交付，不拆成单模块版本。

**功能清单**：

1. 单页网站基础结构，包含个人介绍、个人作品、抖音作品、留言四个区块。
2. IP 与个人信息左右排列；桌面和手机均保持左右布局，窄屏自然换行。
3. 图片和文章在同一内容流单列混排，图片原比例、文章全文展开，顺序手动配置。
4. 抖音卡片显示封面和标题，桌面多列、手机每行两张，点击新标签页打开指定主页。
5. 留言表单：昵称、微信号、留言全部必填，长度 1–30、1–50、1–2000。
6. 校验失败、提交中、成功、失败/超时状态；接收邮箱只在私有服务端配置。
7. 基础响应式布局和可验证的构建/预览流程。

**不做什么**：

- 不做完整视觉精修、复杂动效和高级性能优化。
- 不做后台、数据库、自动抓取、站内视频、图片弹窗或文章详情页。
- 不做多账号、访客账号或公开留言。

**验证点**：

- 四个模块在同一站点可访问，完整主流程能走通。
- 桌面与手机核心内容可读，无横向滚动。
- 图片、文章和抖音卡片按手动配置显示；抖音卡片跳到正确主页。
- 有效留言能触发真实邮件通知；无效输入不会发送。
- 本轮每项以 SPEC 和 TEST-REPORT 实测为准。

**预计工作量**：以具体 SPEC 评估，不在路线图中承诺固定工期。

### V0.2 - 整站数据后台与留言管理

**目标**：在完整前台基础上，建立登录保护的 Supabase 后台，保存留言并查看 UV、PV 和按日期趋势。

**功能清单**：

1. 管理员登录与受保护后台。
2. 留言入库、查看、标记已读、删除。
3. PV、UV、留言数和日期趋势看板。
4. RLS 权限、异常反馈和隐私说明。

**不做什么**：不开放公开后台、不保留邮件通知、不做复杂角色体系或公开留言。

**验证点**：匿名访客只能提交；管理员登录后能查看和管理；未授权读取被拒绝；统计与测试事件一致。

### V0.3 - 整站视觉完整与体验稳定

**目标**：在后台能力可用的整站基础上，完成视觉精修、异常、可访问性和性能。

**目标**：在 V0.1 完整可用的基础上，让整站形成一致、可识别的 Y2K 动漫视觉。

**功能清单**：

1. 定稿色彩、字体、IP 素材、贴纸/像素/动漫装饰和组件规范。
2. 统一四个区块的层级、间距、标题、按钮、卡片、表单和反馈状态。
3. 优化桌面、平板、手机在真实内容下的布局与阅读节奏。
4. 补齐正式作品素材、封面、标题和空态视觉。
5. 更新视觉说明和内容配置文档，保证后续可维护。

**不做什么**：不新增后台、数据库、自动抓取或超出 PRD 的社交功能；不以视觉调整改变已确认的业务规则。

**验证点**：四个模块视觉一致，正式素材替换完成，关键文本清晰，多个真实内容组合下无布局溢出；PRD 核心流程不回归。

### V0.4 - 整站正式发布前稳定性

**目标**：完成跨设备回归、内容配置校验、性能和维护流程。

**目标**：让完整网站在网络、内容和设备差异下保持可理解、可恢复。

**功能清单**：

1. 完善图片失败、作品空态、主页缺失、留言失败/超时和重试体验。
2. 明确键盘焦点、语义标签、对比度、替代文本和可访问性反馈。
3. 优化图片尺寸、加载策略、字体和首屏性能，不牺牲内容完整性。
4. 建立内容配置校验，防止无效链接、重复标识或缺失必填信息进入发布。
5. 建立跨视口回归清单和内容更新流程。

**不做什么**：不建设完整 CMS、复杂监控平台或数据库留言历史；不把未验证的性能数字写成承诺。

**验证点**：异常路径均有用户可理解反馈和恢复方式；键盘/移动/桌面回归通过；内容配置错误在发布前可发现；核心性能以实际测量结果记录。

### V1.0 - 整站正式发布，可对外分享和持续维护

**目标**：把完整、稳定、统一的网站发布到真实环境，并建立可回滚、可备份的维护闭环。

**功能清单**：

1. 生产部署、域名、HTTPS、缓存和错误页面配置。
2. 真实邮件通知、失败重试策略、反垃圾保护与隐私说明。
3. PC、平板和手机完整回归；主流浏览器、外链和素材授权检查。
4. SEO 标题描述、社交分享图、站点图标和基础分享预览。
5. 发布、回退、内容更新、Git 分支、测试与远端备份文档。
6. 以实际测试证据完成发布验收，记录已知问题与监控责任。

**不做什么**：不自动抓取抖音数据，不承诺高级分析、社区、电商或会员体系；未列入 SPEC 的新功能另行评估。

**验证点**：四模块生产环境完整流程通过；真实邮件到件；异常、隐私、性能、可访问性和链接检查有证据；main 与远端 SHA 一致，可按文档回退。

## 版本依赖

V0.1 先建立完整但朴素的整站基线；V0.2 在不改变业务规则的前提下精修视觉；V0.3 在完整视觉基础上补齐异常、可访问性、性能与维护；V1.0 才进入生产发布和长期维护。每轮均先建立 SPEC，开发、测试通过后合并和同步远端。

## 待确认的关键信息

1. 正式 IP、图片、文章、抖音封面与标题素材。
2. 技术栈、邮件服务提供商、超时阈值和部署平台。
3. 字符计数口径（中文、emoji、组合字符）。
4. Y2K 视觉方向、域名和隐私说明文案。
5. 真实环境的反垃圾策略与备份保留周期。

## 下一步行动

1. 为 V0.1 建立独立 SPEC，锁定技术栈、素材清单和验收环境。
2. 按 SPEC 实现完整四模块站点，不先做孤立模块交付。
3. 执行桌面/手机、正常/异常、邮件和隐私测试，输出 TEST-REPORT。
4. 满足合并门槛后合并 main；配置网站专属 origin 后推送分支与 main。
5. V0.1 复盘后再为整站视觉、稳定性和正式发布分别建立新 SPEC。
